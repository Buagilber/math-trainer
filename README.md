# Математика: тренажер для молодшої школи

Вебзастосунок для розв'язування математичних прикладів. Завдання згруповані за класами, розділами й рівнями складності. Мета — швидко потренуватися без підручника й зошита: обрав клас і тему, і застосунок видає набір випадкових прикладів. Зараз є 2 клас (12 розділів, за підручником Скворцової) і 5 клас (14 розділів, за підручником Мерзляка); далі — весь курс НУШ. Застосунок адаптований для телефонів і планшетів (насамперед Android) і встановлюється на головний екран як PWA.

## Як влаштовано

```
index.html, css/            інтерфейс
js/core/                    чиста логіка: без DOM, мережі та сховища
  rng.js                    детермінований генератор випадкових чисел
  expr.js                   парсер і обчислення виразів
  generators.js             генератори прикладів (arithmetic, expression, compare, template, decimal, fraction)
  numbers.js                точна арифметика десяткових і звичайних дробів
  session.js                тренувальна сесія, перевірка відповіді, зірки
  progress.js               прогрес із журналу сесій
  validate.js               перевірка контенту
js/app/                     платформна частина
  main.js                   екрани й навігація (адреси #/grade/g2, #/topic/g2-mul…)
  answer-input.js           поле відповіді й клавіатура під тип відповіді
  content.js                завантаження data/ (без кешу, при кожному запуску)
  storage.js                localStorage і сховище прогресу
js/config.js                налаштування
data/                       контент (JSON), формат описано в docs/CONTENT.md
tests/                      тести core-логіки й контенту (tests/index.html)
sw.js                       service worker: свіжі узгоджені файли після оновлень, робота офлайн
```

Збірки немає: це звичайні ES-модулі, тож репозиторій публікується на GitHub Pages як є.

### Задел під мобільний застосунок

- **Контент не залежить від платформи.** Нативний застосунок читатиме ті самі JSON (з GitHub Pages або вбудовані в застосунок).
- **Правила описані даними, а не кодом.** Завдання задаються декларативно (генератор + параметри), тож у новій мові треба реалізувати лише 6 невеликих генераторів, парсер виразів і точну арифметику дробів з `js/core/`. Їхня поведінка зафіксована в `docs/CONTENT.md` і `tests/core.test.js`, і ці тести можна перенести як специфікацію.
- **Логіка відокремлена від інтерфейсу.** `js/core/` не торкається DOM і сховища. Якщо мобільний застосунок робитимуть на React Native або Capacitor, ці модулі можна взяти без змін.
- **Прогрес зберігається як журнал завершених сесій**, а не як готові лічильники. Такий журнал легко синхронізувати з сервером, коли з'являться акаунти.
- **Сховище прогресу сховане за інтерфейсом** (`storage.js`: `progressStore.all/add/clear`). Щоб перенести прогрес на Supabase чи Firebase, достатньо замінити цей файл. Поле `profileId` у записах уже є на випадок появи профілів.

## Поведінка інтерфейсу

Короткий перелік того, що бачить дитина; деталі — у пов'язаних документах.

- **Клавіатура за типом відповіді.** Цілі числа — цифри, ⌫ і ✓; десяткові — плюс «,»; звичайні дроби — поля «ціла / чисельник / знаменник» і «→»; вибір — кнопки (`<`, `=`, `>`, «Так/Ні»). Молодші класи зайвих кнопок не бачать.
- **Знаки дій кольорові**: `+` зелений, `−` помаранчевий, `×`/`·` фіолетовий, `:` бірюзовий (червоний лишається для помилок). Знак множення задає клас: у 5 класі `·` (`notation` у `catalog.json`).
- **Стовпчик** (`layout: "column"`): розряди під розрядами, знак між числами, поле відповіді під рискою. Відповідь типово вводиться справа наліво; стрілка під полем перемикає напрям, поле при цьому очищується, вибір запам'ятовується.
- **Рівняння з x**: рівняння як у підручнику і рядок «x = □». Для великих чисел — необов'язковий крок «Обрати дію» (4 варіанти, обрана дія рахується стовпчиком) — [EQUATION-STEPS.md](docs/EQUATION-STEPS.md).
- **Підказка 💡** тихо з'являється, якщо дитина довго не відповідає й не вводить відповідь; картка з правилами й схемою назв, на час її показу приклад піднімається — [HINTS.md](docs/HINTS.md).
- **Відповідь.** Правильна — зелене поле й «Молодець!», автоматичний перехід; неправильна — червоне поле, правильна відповідь (для рівнянь — «бо x = …») і «Далі». Вихід посеред тренування — власне вікно підтвердження (якщо вже щось розв'язано).
- **Підсумок сесії.** Зірки (3 — від 90%, 2 — від 70%, 1 — від 50%), «Правильно N з M», середній час на приклад, порівняння з попередньою сесією рівня (спершу точність; швидкість — лише якщо точність не впала), кількість використаних підказок, для рівнянь — нерозв'язані за причинами (неправильна дія / помилка в обчисленні / і те, і те / без вибору дії).
- **Список помилок.** Приклад з підставленою правильною відповіддю й «твоя відповідь ⊗»; для рівнянь — рівняння, твоя відповідь, обрана дія (червона ⊗ або зелена ✓) і «правильно: x = …, бо x = …».
- **Дата останньої сесії** на картці розділу («сьогодні», «вчора», «5 днів тому», «3 тижні тому», «4 місяці тому», «понад рік тому» — за календарними днями).
- **Статистика рівня** на екрані вибору рівня: кількість сесій, точність, коли й за який середній час на приклад пройдено останню сесію.

## Локальний запуск

Потрібен будь-який статичний сервер. Найзручніше — `tools/serve.py`: він вимикає кешування, тож після змін у коді браузер завжди бере свіжі файли. Відкриття `index.html` напряму як файлу не спрацює, бо модулі й `fetch` потребують HTTP.

```bash
python3 tools/serve.py
```

Застосунок: http://localhost:8765. Тести: http://localhost:8765/tests/.

## Екрани й адреси

| Адреса | Екран |
|---|---|
| `#/` | вибір класу (головна) |
| `#/about` | «Про застосунок» |
| `#/grade/g2` | розділи класу |
| `#/topic/g2-mul` | рівні розділу та статистика |
| `#/topic/g2-mul/play`, `/result` | сесія й підсумок (після перезавантаження повертають на рівні розділу) |

При першому запуску на будь-якій адресі спершу показується привітання. Після кнопки «Почати тренування» відкривається запитаний екран. Відмітка про те, що привітання вже бачили, зберігається в браузері (`mt.welcomed`).

Класи перелічені в `data/catalog.json`. Клас без розділів показується як «Незабаром».

## Публікація на GitHub Pages

1. Створіть репозиторій на GitHub і завантажте в нього вміст цієї папки.
2. Відкрийте **Settings → Pages → Build and deployment**, у полі **Source** виберіть *Deploy from a branch*, потім **Branch** `main` і **Folder** `/ (root)`.
3. За хвилину-дві сайт з'явиться за адресою `https://<username>.github.io/<repo>/`.

На безкоштовному тарифі GitHub Pages працює лише з публічними репозиторіями.

### Встановлення на Android

Відкрийте сайт у Chrome, потім **⋮ → Додати на головний екран** (або **Встановити застосунок**). Застосунок відкриватиметься на весь екран без адресного рядка.

## Service worker

`sw.js` працює за принципом «спершу мережа»: кожен запит перевіряється на сервері, тож після публікації всі модулі одразу однієї версії. Збережені копії використовуються, коли мережа підводить: немає з'єднання чи DNS, сервер відповів 5xx, відповідь перенаправлена на чужий сайт (сторінка входу в публічний Wi‑Fi) або мережа не відповіла за 5 секунд. Після такого тайм-ауту наступні 30 секунд копії віддаються одразу, тож за повільної мережі застосунок відкривається приблизно за 5 секунд.

Перевірити поведінку локально можна режимами сервера: `python3 tools/serve.py --delay 8000` (повільна мережа) і `python3 tools/serve.py --fail` (усі відповіді 503). Якщо service worker колись треба аварійно вимкнути, у коментарі на початку `sw.js` є готовий код для цього.
