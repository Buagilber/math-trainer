# Звернення: помилки й пропозиції

Звернення збираються в **GitHub Issues** репозиторію `Buagilber/math-trainer`. Застосунок анонімний, персональних даних у зверненнях немає.

## Як надіслати (користувач)

1. На будь-якому екрані натиснути **⚑** у верхній панелі.
2. Обрати **🐞 Помилка** або **💡 Пропозиція**, коротко описати.
3. «Відкрити GitHub» — відкриється форма нового issue, уже заповнена: заголовок, опис і **контекст екрана**.
4. За бажанням додати скріншот і натиснути **Create**. Потрібен вхід у GitHub.

Сайт статичний, тож застосунок не може створити issue сам (знадобився б токен GitHub, а його не можна викласти в публічний код). Тому останній крок — у GitHub.

## Що містить звернення

Шаблони — `.github/ISSUE_TEMPLATE/app-bug.yml` і `app-idea.yml`. Кожне звернення має:

- **заголовок** `[Помилка] …` або `[Пропозиція] …` (перший рядок опису);
- **мітки** `bug` або `enhancement`, `from-app`, `needs-triage`;
- розділ **«Що не так» / «Що запропонувати»** — текст користувача;
- розділ **«Скріншот»** — якщо додали;
- розділ **«Контекст»** — YAML-блок, який заповнює застосунок (`js/app/main.js` → `reportContext`):

| Поле | Коли є | Що означає |
|---|---|---|
| `екран` | завжди | адреса екрана (`#/topic/g2-mul/play`) |
| `час` | завжди | момент натискання ⚑ (UTC) — за ним видно версію коду в історії комітів |
| `клас`, `розділ` | екрани класу й розділу | назва й id розділу |
| `рівень`, `приклад`, `завдання` | тренування | рівень, номер прикладу, **id завдання в `data/topics/<розділ>.json`** |
| `текст`, `правильна відповідь`, `введено`, `стан` | тренування | що бачила дитина, що вважається правильним, що введено, чи вже перевірено |
| `підказка`, `крок «Обрати дію»`, `напрям введення` | тренування, якщо доречно | стан підказки, обрана дія в рівнянні, напрям введення в стовпчику |
| `результат`, `помилки` | підсумок | правильно N з M і список помилок з id завдань |
| `пристрій`, `розмір екрана`, `режим` | завжди | user agent, розмір вікна, браузер чи встановлений застосунок |

## Розбір агентом

Агент запускається за розкладом (наприклад, щодня) і обробляє нові звернення.

**1. Знайти нові:**
```bash
gh issue list -R Buagilber/math-trainer --label needs-triage --state open --json number,title,body,labels,createdAt
```

**2. Для кожного звернення:**
- прочитати опис і контекст; відтворити за `розділ` + `завдання` (знайти завдання в `data/topics/…`) і за `текст`/`правильна відповідь`;
- перевірити, чи це не дубль відкритого issue (тоді — мітка `duplicate` і посилання на оригінал, закрити);
- поставити мітки: клас (`grade-2`, `grade-5`), область (`area:content` — тексти й завдання, `area:ui` — вигляд, `area:logic` — генерація, перевірка, статистика), пріоритет (`p1` — ламає тренування, неправильна відповідь зараховується/не зараховується; `p2` — заважає; `p3` — косметика, ідеї);
- написати коментар: **що відтворено, ймовірна причина (файл/завдання), пропонований план виправлення й обсяг**;
- зняти `needs-triage`, поставити `plan-proposed`.

**3. Підсумок розбору** — короткий звіт: скільки нових, які `p1`, що пропонується робити першим.

## Правило: виправлення — лише за погодженням

Агент **не змінює код і дані** за зверненнями самостійно. Виправлення починається, лише коли власник поставив мітку `approved` (або погодив у чаті). Після виправлення — коміт з посиланням на issue (`Fixes #N`), коментар з тим, що змінено, і закриття issue.

## Статуси (мітки)

`needs-triage` → `plan-proposed` → `approved` → закрито комітом. Відхилені — `wontfix` або `invalid` з поясненням.
