# Формат контенту

Усі завдання лежать у `data/` у вигляді JSON. Застосунок завантажує їх під час кожного запуску, тому зміни в коді для нового контенту не потрібні: відредагували JSON, закомітили, і за хвилину-дві GitHub Pages публікує оновлення.

Перевірити контент після змін можна на сторінці `tests/index.html`. Тест «весь контент з data/ валідний» генерує по 200 прикладів з кожного завдання і повідомляє, якщо щось зламано. Зламане завдання застосунок просто пропускає й показує попередження внизу екрана розділів.

## Структура

```
data/
  catalog.json          — класи і список розділів
  topics/<id>.json      — один файл на розділ
```

### catalog.json

```json
{
  "version": 1,
  "levels": { "1": "Легко", "2": "Середньо", "3": "Складно" },
  "grades": [
    { "id": "g2", "grade": 2, "title": "2 клас", "topics": ["topics/g2-mul.json"] }
  ]
}
```

Щоб додати розділ, створіть файл у `topics/` і додайте шлях до нього в `topics` потрібного класу. Порядок у списку відповідає порядку на екрані. Новий клас додається новим об'єктом у `grades`.

### Розділ (topics/*.json)

| Поле | Обов'язкове | Опис |
|---|---|---|
| `id` | так | Унікальний ідентифікатор. **Не змінюйте після публікації**, бо до нього прив'язаний прогрес |
| `title` | так | Назва розділу |
| `icon` | ні | Емодзі для картки |
| `sessionSize` | ні | Скільки прикладів в одному тренуванні (за замовчуванням 10) |
| `exercises` | так | Масив завдань |

### Завдання (exercises[])

Спільні поля:

| Поле | Опис |
|---|---|
| `id` | Унікальний у межах розділу, не змінюйте після публікації |
| `kind` | `"generator"` (генерує нові приклади щоразу) або `"fixed"` (конкретне завдання) |
| `difficulty` | Рівень 1, 2 або 3 (за замовчуванням 1) |
| `weight` | Як часто з'являється порівняно з іншими завданнями рівня (за замовчуванням 1) |

Символ `□` у тексті позначає місце для відповіді. Якщо `□` у тексті немає (як у текстових задачах), поле відповіді виводиться під текстом.

## Фіксоване завдання

```json
{ "id": "m-cm", "kind": "fixed", "difficulty": 1, "text": "1 м = □ см", "answer": 100 }
```

З вибором варіанта:

```json
{ "id": "q1", "kind": "fixed", "text": "5 дм □ 48 см", "answer": ">", "choices": ["<", "=", ">"] }
```

Додаткові поля: `unit` (одиниця біля поля відповіді) і `shuffleChoices: true` (перемішувати варіанти).

## Генератори

### Значення змінних

Змінні використовуються в генераторах `template`, `expression` і `compare`, а формат `[min, max]` також у параметрах `a` і `b` генератора `arithmetic`:

| Запис | Значення |
|---|---|
| `[1, 9]` | ціле від 1 до 9 |
| `[10, 90, 10]` | від 10 до 90 з кроком 10 (10, 20, …, 90) |
| `{ "oneOf": ["Марійка", "Оленка"] }` | один з варіантів (зокрема текстовий) |

### Вирази

У формулах доступні `+ - * / %`, дужки й порівняння `< > <= >= == !=`. Ділення завжди має бути без остачі, інакше варіант відкидається і генерується новий. На екрані `*` показується як `×`, `/` як `:`, а `-` як `−`.

### `arithmetic`: приклади a ○ b = c

```json
{ "id": "two-one", "kind": "generator", "generator": "arithmetic", "difficulty": 1,
  "params": { "op": ["+", "-"], "a": [11, 98], "b": [1, 9], "result": [0, 100], "carry": "forbidden" } }
```

| Параметр | Опис |
|---|---|
| `op` | `"+"`, `"-"`, `"*"`, `"/"` або масив операцій |
| `a`, `b` | Діапазони компонентів. Для `/`: `b` задає дільник, `a` (необов'язково) обмежує ділене |
| `result` | Діапазон результату. Для `/` це діапазон частки |
| `carry` | `"required"` (лише з переходом через десяток), `"forbidden"` (лише без переходу), `"any"` |
| `missing` | Що приховати: `"result"` (за замовчуванням), `"a"`, `"b"`, `"operand"` (a або b), `"any"` |
| `commutative` | `true`: випадково міняє a і b місцями (для таблиці множення) |

### `expression`: обчисли значення виразу

```json
{ "id": "brackets", "kind": "generator", "generator": "expression", "difficulty": 2,
  "params": { "expr": ["a - (b + c)", "(a - b) + c"], "vars": { "a": [20, 80], "b": [2, 30], "c": [2, 30] },
              "result": [0, 100], "steps": [0, 100] } }
```

`expr` містить один вираз або масив виразів. `result` обмежує відповідь, `steps` обмежує кожен проміжний результат (щоб не виходити за межі 100 у проміжних діях).

### `compare`: постав знак <, = чи >

```json
{ "id": "expr-number", "kind": "generator", "generator": "compare", "difficulty": 2,
  "params": { "left": { "expr": "a + b", "vars": { "a": [10, 70], "b": [2, 29] }, "result": [0, 100] },
              "right": { "near": 5 } } }
```

Кожна сторона описується одним із трьох способів:
- `{ "number": [min, max] }`: число;
- `{ "expr": "...", "vars": {...}, "result": [...] }`: вираз;
- `{ "near": n }` (лише права сторона): число, що відрізняється від лівої частини не більше ніж на n.

`equalShare` (від 0 до 1, за замовчуванням 0.3) визначає, яку частку випадків, коли сторони рівні, залишати.

### `template`: довільний текст із формулою відповіді

Підходить для текстових задач, величин, периметра тощо.

```json
{ "id": "had-gave", "kind": "generator", "generator": "template", "difficulty": 1,
  "params": {
    "text": "У {name} було {a} {a|яблуко|яблука|яблук}. Вона віддала {b}. Скільки залишилось?",
    "vars": { "name": { "oneOf": ["Марійки", "Оленки"] }, "a": [5, 20], "b": [1, 9] },
    "where": ["a > b"],
    "answer": "a - b",
    "unit": "ябл."
  } }
```

| Параметр | Опис |
|---|---|
| `text` | Текст з підстановками (див. нижче) |
| `vars` | Змінні |
| `where` | Умови, які мають виконуватися (масив виразів) |
| `answer` | Формула відповіді |
| `result` | Діапазон відповіді (за замовчуванням ≥ 0) |
| `steps` | Діапазон проміжних результатів формули |
| `unit` | Одиниця біля поля відповіді |

Підстановки в `text`:

| Запис | Результат (a = 3, b = 5) |
|---|---|
| `{a}` | `3` |
| `{a * 10 + b}` | `35` |
| `{=a + b}` | `3 + 5` (вираз у шкільному записі) |
| `{a\|гриб\|гриби\|грибів}` | `гриби` (форма слова для числа: 1 / 2–4 / 5+) |
| `{name}` | значення текстової змінної |

## Поради

- Після змін відкрийте `tests/index.html`. Якщо обмеження неможливо виконати (наприклад, `carry: "required"` при `a: [1, 2]`), тест покаже помилку.
- Не змінюйте `id` опублікованих розділів і завдань, бо від них залежить прогрес. Щоб прибрати завдання, видаліть його. Щоб змінити суть завдання, створіть нове з новим `id`.
- Кожен рівень розділу має містити хоча б одне завдання. Якщо рівня немає, він просто не показується.
